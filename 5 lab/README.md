# Лабораторная №5 · Student Management

Перенос frontend системы управления студентами с Vue на **Nuxt**. Основные темы работы — серверный рендеринг, файловая маршрутизация, авторизация, работа с API и кеширование данных.

**Стек:** Nuxt 4.6.4 · Vue 3 · TypeScript · Java 17 / Spring Boot · PostgreSQL · Docker.

## Обзор

| Часть | Содержание |
| --- | --- |
| Пользователь | Регистрация, вход по JWT, профиль, выход, роли USER и ADMIN |
| Студенты | Список и карточка, поиск, фильтры, сортировка, пагинация |
| Действия ADMIN | Добавление, редактирование и удаление студентов |
| Nuxt | SSR, динамический маршрут `/students/[id]`, middleware, состояния загрузки и ошибок, 404 |
| Данные и запуск | Кеширование с обновлением после изменений, изоляция сессий, Docker |

`id` в адресе карточки — ИСУ студента (`ISU` в Java DTO). Профиль API содержит `username` и `role`. Поиск текстовых полей в текущем Java backend выполняется по точному совпадению.

## Архитектура

```text
Браузер → Nuxt → Java API → PostgreSQL
          SSR     JWT, права,
          UI      бизнес-логика
```

Nuxt отвечает за интерфейс, маршруты и получение данных. Java backend из [лабораторной №3](../3%20lab/README.md) — за авторизацию, проверку прав, обработку данных и БД. Основой интерфейса служат компоненты и стили [лабораторной №4](../4%20lab/README.md).

Браузер обращается к `/api/backend` на своём origin; сервер Nuxt использует приватный адрес Java API. Схема сессии: JWT в HttpOnly-cookie → Bearer в запросах Nuxt к Java. Токены не должны попадать в HTML и клиентское состояние; персональные данные не должны храниться в общем серверном кеше. Проверка маршрута не заменяет проверку роли в Java.

## Локальный запуск

Нужен **Node.js 24.15+ в ветке 24** (проверено на 24.21.0) и npm. Java backend и PostgreSQL запускаются отдельно по инструкции третьей работы.

Из папки `5 lab` в PowerShell:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm.cmd ci
npm.cmd run dev
```

Приложение: **http://localhost:3000**. На Linux/macOS используйте `npm` вместо `npm.cmd`.

| Переменная | Значение для локального запуска |
| --- | --- |
| `NUXT_JAVA_API_BASE` | `http://localhost:8080/api` — Nuxt → Java |
| `NUXT_PUBLIC_API_BASE` | `/api/backend` — браузер → Nuxt |
| `NUXT_COOKIE_SECURE` | `false` для HTTP; `true` для HTTPS |

В Git сохраняются `.env.example` без секретов и `package-lock.json`. Настоящий `.env`, JWT, пароли, ключи, дампы, `node_modules`, `.nuxt` и `.output` не публикуются.

## Сборка и Docker

```powershell
npm.cmd run typecheck
npm.cmd run build
npm.cmd run preview
```

Production-запуск: `npm.cmd start`. Переменные окружения передаются процессу явно: production-сервер не загружает `.env` автоматически.

```powershell
docker build -t student-management-lab5 .
docker run --rm -p 3000:3000 --env-file .env -e NUXT_JAVA_API_BASE=http://host.docker.internal:8080/api student-management-lab5
```

Команда рассчитана на Docker Desktop и Java на хосте. В общей Docker-сети адрес Java задаётся именем её сервиса, например `http://backend:8080/api`. `localhost` внутри контейнера указывает на сам контейнер. На Linux для обращения к хосту может потребоваться `--add-host=host.docker.internal:host-gateway`.

## Проверки перед завершением

Чеклист отмечается только после фактической проверки результата.

- [ ] **Чистая установка:** `npm ci`, `npm run typecheck` и `npm run build` завершаются без ошибок; собранный сервер запускается.
- [ ] **Авторизация:** регистрация, вход, ошибочный пароль, F5, истечение access, обновление токенов и выход; повторный запрос после refresh выполняется не более одного раза. Ротация работает при параллельных запросах и в двух вкладках, SSR Set-Cookie доходит до браузера.
- [ ] **Роли:** гость перенаправляется на вход; USER читает данные, но не изменяет их; ADMIN выполняет CRUD. Прямой запрещённый запрос к Java возвращает 403; redirect после входа не допускает внешний адрес.
- [ ] **SSR и маршруты:** данные списка/карточки есть в исходном HTML, гидратация не дублирует первый запрос. Прямое открытие и обновление `/students/[id]` и страницы редактирования работают; переход между разными ИСУ обновляет карточку.
- [ ] **Поиск и список:** фильтры сочетаются с сортировкой и пагинацией, `false` не теряется, первая страница имеет номер 0. F5 сохраняет условия URL; быстрый ввод отменяет старый запрос, устаревший ответ не заменяет новый.
- [ ] **CRUD:** создание, редактирование с неизменным ИСУ, подтверждение/отмена удаления, ошибки 409/422, сохранение введённых данных при ошибке и защита от повторной отправки. Удаление корректно обрабатывает 204 без JSON.
- [ ] **Кеш:** после изменений список и карточка обновляются, удаление последней строки корректирует страницу. Проверены повторное открытие и истечение срока кеша; выход и смена пользователя очищают персональные данные.
- [ ] **Ошибки:** загрузка, пустой результат, повтор запроса, недоступность Java и ответы 401/403/404/5xx. Неизвестный URL и отсутствующий студент возвращают HTTP 404; сетевой сбой не маскируется под отсутствие записи или выход.
- [ ] **Интерфейс:** формы, таблица и меню удобны на ширине 360/768/1280 px; работают клавиатура, фокус и сообщения об ошибках.
- [ ] **Сессии и секреты:** два независимых пользователя не получают чужие данные; JWT отсутствует в HTML, payload и логах. Проверены HttpOnly/SameSite/Secure, защита изменяющих запросов от CSRF и отсутствие общего HTTP-кеша персональных страниц.
- [ ] **Docker и сдача:** контейнер действительно собран и запущен, Java доступна из него, вложенные страницы обновляются. Напарник повторил запуск по README; в коммит не попали секреты и реальные персональные данные.
