# Памятка к защите лабораторной №4 — Vue

Приложение ведёт список студентов общежития. USER смотрит список, фильтрует, сортирует и открывает карточку; ADMIN также создаёт, редактирует и удаляет студентов. Есть регистрация, вход, профиль и выход. Backend взят из `../3 lab`.

## Как проходит запрос

Пример создания: `src/components/StudentForm.vue` собирает поля и проверяет формат → `src/pages/StudentCreatePage.vue` вызывает действие Pinia → `src/stores/students.js` вызывает `src/api/students.js` → `src/api/http.js` отправляет JSON и access JWT через fetch → Vite proxy локально или Nginx в Docker передаёт `/api/admin/students` в Spring → `SecurityConfig` и `JwtAuthenticationFilter` проверяют токен и ADMIN → `StudentController` принимает DTO и запускает валидацию → `StudentService` проверяет бизнес-условия → `StudentRepository` через EclipseLink/JPA сохраняет запись в PostgreSQL. Ответ возвращается обратно; Vue открывает карточку, полученную с сервера.

Java-классы находятся в `../3 lab/src/main/java/dev/geeks/studentmanagement/`: `config/`, `security/`, `student/`, `auth/`. Ошибки API формирует `common/error/GlobalExceptionHandler.java`, frontend показывает их через `ErrorMessage.vue` или сообщение формы.

## Инструменты в нашем коде

| Тема | Для чего нужна и где реализована |
| --- | --- |
| Vue 3, Composition API | Компоненты описывают интерфейс; ref/reactive хранят реактивные данные, computed вычисляет значения. Пример — `src/pages/StudentsPage.vue`, общая форма — `src/components/StudentForm.vue`. |
| Компоненты, props, emit, v-model | Родитель передаёт данные через props, ребёнок сообщает о действии через emit. `StudentForm` отправляет submit, `SearchInput` поддерживает v-model через modelValue и update:modelValue. |
| Vue Router | Меняет страницы без полной загрузки документа, извлекает ISU из URL, проверяет вход и роль через beforeEach. `src/router/index.js`. |
| Pinia | Делит состояние между страницами: пользователь и токены в `src/stores/auth.js`, список, карточка, ошибки и пагинация в `src/stores/students.js`. |
| RxJS | Организует поток поисковых запросов. `src/composables/useStudentSearch.js`: Subject принимает параметры, distinctUntilChanged убирает повторы, switchMap отменяет предыдущую работу, timer даёт debounce 300 мс. |
| Отмена HTTP | Observable создаёт AbortController и передаёт signal в fetch; отписка вызывает abort. catchError внутри запроса сохраняет поток после ошибки, onUnmounted удаляет подписку. |
| Access JWT | Короткоживущий подписанный пропуск для API, передаётся в Authorization: Bearer. `src/api/http.js`, backend `security/JwtService.java` и `JwtAuthenticationFilter.java`. |
| Refresh JWT | Позволяет получить новую пару без пароля. Backend хранит refresh-сессию в БД, проверяет срок и отзыв, при обновлении отзывает прежнюю. `auth/AuthService.java`, `auth/model/RefreshSession.java`. |
| Nginx | Раздаёт готовый dist, возвращает index.html для вложенных SPA URL, проксирует `/api/` с сохранением пути. `nginx.conf`. |
| Docker Compose | Соединяет frontend, backend и PostgreSQL в одной сети, передаёт настройки, хранит БД и ключи в volumes, задаёт ожидание готовности. `compose.yaml`. |
| Multi-stage сборка | Node собирает frontend, Maven собирает backend; итоговые образы содержат Nginx со статикой и JRE с jar соответственно. `Dockerfile`, `Dockerfile.backend`. |

## Короткие ответы

Файл ТЗ №4 в репозитории не найден. Ниже ответы по темам реализации, а не предполагаемый официальный список вопросов.

- **Что такое SPA?** Один HTML-документ, содержимое страниц переключает Vue Router; данные приходят JSON-запросами.
- **Почему F5 на карточке работает?** Nginx возвращает index.html, затем Router читает URL; Pinia восстанавливает пользователя через `/api/auth/me` с сохранёнными токенами.
- **Зачем debounce и switchMap вместе?** Задержка не даёт отправлять запрос на каждую букву; switchMap отписывает старый запрос, а AbortController останавливает fetch. Устаревший ответ дополнительно защищён номером запроса в store.
- **Где выполняются поиск и пагинация?** На сервере в `StudentService.list`: все фильтры соединяются AND, сортировка проверяется по разрешённым полям, PageRequest задаёт страницу и размер. При одинаковом значении сортировки дополнительный порядок по ISU делает страницы стабильнее. Текстовый поиск точный, с учётом регистра.
- **Что происходит при 401?** HTTP-клиент использует общий refresh Promise, получает новую пару и повторяет запрос один раз. При окончательном 401 очищает сессию. 403 означает недостаток прав и не вызывает refresh.
- **Достаточно скрыть кнопку ADMIN?** Нет. Router и кнопки помогают пользователю, реальные права проверяет Spring Security на каждом API-запросе. Регистрация создаёт только USER.
- **JWT шифрует данные?** Нет, подпись защищает от подделки, содержимое можно прочитать. Пароли в JWT не кладутся; в БД хранится BCrypt-хеш пароля.
- **Как устроен выход?** Отзывается refresh-сессия, браузер очищает токены и данные Pinia. Выданный access не отзывается немедленно и действует до своего срока.
- **Как предотвращается повторная отправка?** pending блокирует кнопки; форма дополнительно проверяет pending в обработчике. Сервер повторно валидирует данные и отклоняет дубликат ISU.
- **Что сохраняется при пересоздании контейнеров?** PostgreSQL в postgres-data и ключи подписи в jwt-keys. `docker compose down` их сохраняет; `down --volumes` применять нельзя, если данные нужны.
- **Зачем миграция?** Старый EclipseLink сохранял expiresat как bytea. Скрипт вручную исправляет тип, удаляя только несовместимые refresh-сессии; исправленную базу повторно не очищает. Пользователи и студенты сохраняются.

## Что показать

Вход USER → список → фильтр, сортировка, переход страниц → запрет создания → выход → вход ADMIN → создание, карточка, редактирование и удаление тестовой записи → F5 на вложенном URL. В исходниках показать RxJS, Router guard, HTTP refresh и Compose volumes. Команды запуска и миграции — в README. Последние изменения требуют проверки запуском; при подготовке выполнялся только анализ исходников.
