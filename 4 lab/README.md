# Лабораторная №4: каркас Vue

Минимальная SPA на JavaScript: Vue 3, Composition API, `<script setup>`, Vite, Vue Router, Pinia и место для RxJS-поиска. Работают только запуск и переходы между заготовками. Запросов, JWT, CRUD, проверок доступа и валидации пока нет; формы и кнопки операций отключены. Параметр ИСУ в примере ссылки не означает существование записи.

`src/pages` — страницы, `src/components` — части интерфейса, `src/stores` — Pinia, `src/api` — транспорт и контракты, `src/composables` — будущий RxJS-поток. Подробные комментарии находятся непосредственно в исходниках. Backend используется из `../3 lab`; предыдущие лабораторные не изменяются.

## Что установить напарнику

Для запуска frontend нужны **Git** и **Node.js 24 с npm** (npm входит в установку Node.js). После установки перезапустите терминал и проверьте:

На Windows скачайте установщики Git и Node.js 24 с официальных сайтов проектов. В установщике Node.js оставьте компоненты npm и добавление в `PATH` включёнными. Редактор можно выбрать любой, например VS Code; для самого запуска он не обязателен. Откройте новое окно PowerShell после установки — старый терминал может ещё не видеть новые команды.

```powershell
git --version
node --version
npm.cmd --version
```

Vue, Vite, Vue Router, Pinia и RxJS отдельно или глобально устанавливать не нужно: команда `npm.cmd ci` установит версии из `package-lock.json` в локальную папку `node_modules`. Для просмотра каркаса Java, Maven, PostgreSQL и Docker не требуются.

| Инструмент | Для чего используется |
| --- | --- |
| Vue 3 | Компоненты интерфейса; Composition API и `<script setup>` |
| Vite | Сервер разработки, обработка `.vue` и сборка сайта |
| Vue Router | Переходы между страницами без полной перезагрузки |
| Pinia | Подключена как система глобального состояния; хранилища пока заготовки |
| RxJS | Установлен для будущего реактивного поиска; сам поток пока не реализован |
| JavaScript | Язык исходников этой лабораторной; TypeScript не требуется |

Первое скачивание зависимостей требует интернета. Команда `npm.cmd ci` использует готовый lock-файл и заново создаёт `node_modules`; вручную менять эту папку не нужно.

## Первый локальный запуск

Если репозиторий ещё не скачан:

```powershell
git clone https://github.com/qulin-ds/student-management.git
cd student-management
```

Если репозиторий уже есть, перейдите в его корень и выполните `git pull --ff-only`. Затем:

Если есть собственные незавершённые изменения, сначала сохраните их своим коммитом или другим привычным способом. Если Git сообщает о конфликте или расхождении веток, не удаляйте файлы и не применяйте `reset --hard`: сначала согласуйте изменения с напарником.

```powershell
cd "4 lab"
Copy-Item .env.example .env
npm.cmd ci
npm.cmd run dev
```

Открыть http://localhost:5173. На системах без ограничения PowerShell можно использовать обычный `npm`.
Для остановки сервера нажмите `Ctrl+C`. При следующих запусках достаточно `npm.cmd run dev` из `4 lab`; после обновления `package-lock.json` повторите `npm.cmd ci`.

Что делает каждая команда:

1. `cd "4 lab"` открывает папку с `package.json`; кавычки нужны из-за пробела в имени.
2. `Copy-Item .env.example .env` создаёт личную конфигурацию. Выполняйте только если `.env` ещё нет, чтобы не заменить свои настройки.
3. `npm.cmd ci` устанавливает все зависимости, включая фреймворк и инструменты сборки.
4. `npm.cmd run dev` запускает Vite. Оставьте этот терминал работающим, пока пользуетесь сайтом. Изменения сохранённых исходников будут подхватываться сервером разработки.

Ожидаемый результат: открывается список-заготовка, доступны переходы к входу, регистрации, профилю, созданию, карточке и редактированию. Формы и кнопки операций отключены специально. Это не ошибка установки: бизнес-логика оставлена для самостоятельной реализации. Неизвестный адрес, например `/unknown`, показывает страницу 404.

`.env` — личный локальный файл, он не попадает в Git. В репозитории хранится только `.env.example` с примерами настроек и пустыми полями паролей. Для просмотра каркаса значения по умолчанию менять не нужно. `node_modules`, `.npm-cache` и `dist` также не отправляются в Git.

Backend для просмотра каркаса не требуется. Его отдельный запуск описан в [README лабораторной №3](../3%20lab/README.md). Dev proxy направляет `/api` на `API_PROXY_TARGET` из `.env` (по умолчанию http://localhost:8080).

### Локальные настройки

| Переменная | Значение и назначение |
| --- | --- |
| `VITE_API_BASE_URL=/api` | Публичный префикс запросов браузера; используется будущим HTTP-клиентом |
| `API_PROXY_TARGET=http://localhost:8080` | Адрес отдельно запущенного backend для dev proxy Vite |
| `FRONTEND_PORT=8084` | Порт сайта при запуске через Compose; на порт Vite не влияет |
| `DB_PASSWORD` | Личный пароль новой учебной БД в Compose; для просмотра только frontend не нужен |
| `ADMIN_USERNAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Необязательные настройки создания администратора backend в Compose |

После изменения `.env` остановите и снова запустите Vite. Переменные с префиксом `VITE_` могут попасть в браузерную сборку: не записывайте туда пароли базы или секреты JWT. `.env` лабораторной №4 не настраивает автоматически отдельно запущенную лабораторную №3 — у неё свой способ передачи настроек.

### Backend без Docker

Для отдельного локального запуска backend понадобятся JDK 17, Maven и PostgreSQL. Подробная установка и подготовка базы уже описаны в README лабораторной №3, поэтому её настройки здесь не дублируются. Запустите backend в отдельном терминале по той инструкции, затем frontend в `4 lab` командой `npm.cmd run dev`.

Если backend слушает другой адрес, измените `API_PROXY_TARGET` и перезапустите Vite. Исходники Java продолжают находиться в `3 lab`; переносить их в `4 lab` не нужно. Пока API-заглушки не реализованы, Vue-приложение не выполняет запросов даже при запущенном backend.

## Проверка сборки

Из папки `4 lab`:

```powershell
npm.cmd run build
npm.cmd run preview
```

Preview показывает сборку на http://localhost:4173; API proxy настроен для dev, production proxy находится в Nginx.

`build` создаёт папку `dist` с HTML, CSS и JavaScript для браузера. `preview` запускает локальный просмотр этих файлов, а не режим разработки. Не открывайте `dist/index.html` двойным щелчком через `file://`: для модулей и маршрутизации используйте HTTP-сервер. Сборка не отправляет сайт в интернет и не запускает backend.

Ожидаемый результат проверки: команда завершается без ошибок, появляется `dist`, через preview открываются страницы-заготовки. После изменения исходников сначала повторите `build`, чтобы preview показывал новую версию.

## Docker Compose

Для совместного запуска frontend, backend и базы установите и запустите **Docker Desktop с Docker Compose** и поддержкой Linux-контейнеров. Проверка: `docker --version` и `docker compose version`. В этом варианте Node.js, Java, Maven и PostgreSQL на компьютере устанавливать не нужно: сборка и запуск выполняются в контейнерах.

Из папки `4 lab` скопируйте `.env.example` в `.env`, если ещё не сделали этого. В `.env` задайте собственный непустой `DB_PASSWORD`; необязательные `ADMIN_USERNAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` создают администратора при первом запуске. Пустые ADMIN-поля оставляют создание администратора выключенным. Не отправляйте заполненный `.env` напарнику через Git.

```powershell
docker compose config --quiet
docker compose up --build
```

Открыть http://localhost:8084. Compose создаёт отдельную учебную PostgreSQL и собирает Java 17 backend непосредственно из `3 lab` через `Dockerfile.backend`. Frontend собирается многоэтапно и раздаётся Nginx; `/api` проксируется без удаления префикса. Данные БД и созданные backend ключи JWT сохраняются в именованных volumes. Готовности backend дождаться по его логам.

`docker compose config --quiet` проверяет конфигурацию и обязательные значения без вывода заполненных паролей. `docker compose up --build` собирает образы и запускает сервисы с логами в текущем терминале. При первом запуске скачивание образов и Maven/npm-зависимостей может занять несколько минут.

| Сервис | Что выполняется |
| --- | --- |
| `frontend` | Nginx на порту 8084, статика Vue, возврат `index.html` для вложенных SPA-адресов |
| `backend` | Spring Boot на внутреннем порту 8080; браузер обращается к нему через `/api` на порту frontend |
| `db` | Отдельная PostgreSQL с базой `student_management` и пользователем `lab4` внутри Docker |

Порты базы и backend на компьютер не публикуются. Установленная на компьютере PostgreSQL этому стенду не нужна. ADMIN создаётся только сервером: для него заполните сразу все три `ADMIN_*` значения, имя и email должны быть свободны, пароль — соответствовать правилам backend. Публичная регистрация создаёт USER. Создание ADMIN не включает ещё не реализованные операции Vue-каркаса.

Для работы в фоне и просмотра состояния из `4 lab`:

```powershell
docker compose up --build -d
docker compose ps
docker compose logs -f backend
```

`Ctrl+C` завершает просмотр логов. Для остановки контейнеров:

```powershell
docker compose down
```

Обычный `down` сохраняет именованные volumes. Не добавляйте `--volumes` или `-v`, если хотите сохранить студентов, пользователей и ключи. Не меняйте `DB_PASSWORD` после создания базы в надежде автоматически изменить пароль существующего PostgreSQL-пользователя: начальные переменные применяются при создании новой базы.

Проверка после запуска: откройте `/students/100000/edit` на порту 8084 и обновите страницу — должна остаться SPA-заготовка. Запрос к `http://localhost:8084/api/auth/me` без токена должен вернуть JSON со статусом 401. Это нормальный ответ защиты backend. В текущей среде проверена сборка Vite; контейнерный запуск не проверен, поскольку Docker недоступен.

## Частые проблемы при запуске

| Симптом | Что сделать |
| --- | --- |
| `node`, `npm` или `git` не распознаны | Проверить установку и `PATH`, полностью перезапустить терминал и редактор |
| PowerShell запрещает запуск `npm.ps1` | Использовать команды `npm.cmd` из этой инструкции; менять политику выполнения не требуется |
| `package.json` не найден | Перейти в `student-management/4 lab`, а не запускать npm из корня репозитория |
| Установка npm завершилась ошибкой | Проверить интернет, доступ к npm registry и полный текст ошибки; повторить `npm.cmd ci` после устранения причины |
| `npm ci` сообщает о несовпадении lock-файла | Получить согласованные `package.json` и `package-lock.json` из Git; не удалять lock-файл ради обхода ошибки |
| Порт 5173 или 4173 занят | Проверить фактический адрес в выводе Vite либо остановить свой прежний сервер |
| Формы не отправляются и студенты не появляются | Это ожидаемое поведение заготовок: запросы и операции ещё не реализованы |
| Изменение `.env` не влияет на Vite | Перезапустить dev-сервер; для изменения публичных настроек в Docker пересобрать frontend |
| Docker не подключается к серверу | Запустить Docker Desktop и дождаться готовности Linux-контейнеров |
| Compose требует `DB_PASSWORD` | Создать `4 lab/.env` из примера и задать свой непустой пароль |
| Порт 8084 занят | Изменить `FRONTEND_PORT` в `.env` и повторить `docker compose up --build` |
| Nginx возвращает 502 при старте | Проверить `docker compose ps` и логи backend; порядок старта не означает готовность Java-приложения |
| Backend не подключается к БД в Compose | Проверить логи `db`/`backend` и соответствие пароля уже созданной базе |

## Совместная работа через Git

В репозиторий входят исходники, конфигурации, `package.json`, `package-lock.json` и пустой шаблон `.env.example`. Личные `.env`, пароли, `node_modules`, `.npm-cache` и `dist` остаются на своём компьютере. Каждый участник самостоятельно устанавливает зависимости командой `npm.cmd ci`.

Перед началом работы получайте изменения из корня репозитория командой `git pull --ff-only`, сохранив свои незавершённые изменения. После обновления зависимостей повторите установку в `4 lab`. Перед своим коммитом проверяйте `git status` и состав изменений; комментарии и сообщения коммитов пишите по-русски. GitHub хранит код: push сам по себе не запускает сайт и backend у напарника.
